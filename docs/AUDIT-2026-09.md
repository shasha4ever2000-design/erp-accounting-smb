# ERP Accounting audit (September 2026)

A full read-through of the accounting engine (`src/store.js`), the reports, the
sync and backup code, and the security-sensitive parts. Every bug listed as
fixed was reproduced with a test first. The new tests are in
`test/auditFixes.test.js`. 14 of its 17 tests fail on the old code and all of
them pass now. The full suite is 2,125 tests, all passing, and the production
build works.

## Bugs fixed

| # | Area | What was wrong | Impact |
|---|------|----------------|--------|
| 1 | Journal entries | An entry could post with debits and credits up to **0.05 apart**. | A hand-typed entry 4 cents out went into the ledger, and the trial balance was off with no clue why. Now it must balance to under half a cent. |
| 2 | Ledger seal (hash chain) | Deleting **any** document (invoice, bill, payroll run, asset, credit note...) removed its journal entries without re-chaining. Editing an invoice did the same. | The integrity check reported normal edits and deletes as **tampering**. That is a false alarm in the one feature meant to catch real tampering. |
| 3 | Kits / bundles | Voiding or editing an invoice put back **the kit** (which holds no stock) instead of its **components**. | Void: components never came back, and a "phantom" kit appeared in stock. Edit: components were **taken out twice**. |
| 4 | FIFO cost layers | Voids, invoice edits and customer returns added quantity back without adding a cost layer. | Stock quantity and FIFO layers drifted apart, so later cost of sales was wrong. Under average cost, returned stock also came back at today's cost instead of what it really cost. |
| 5 | Delete credit note | Deleting a sales-return credit note removed only the credit entry. | The goods stayed on the shelf, the cost-of-sales reversal stayed in the ledger, and the invoice line stayed marked "returned", so it could never be returned again. |
| 6 | Delete debit note | Same problem for purchase returns. | Stock and the bill's returned quantity were never put back. |
| 7 | Payments after a return | Payment limits ignored returns. On an invoice of 1,000 with a 400 return, the app still accepted 1,000. | Accounts Receivable went to **-400**. Same for supplier bills and Accounts Payable. The invoice and bill screens also showed the wrong "Balance Due". |
| 8 | Trial Balance | Titled "As at {end date}" but included **every entry ever posted**, including later ones. The export had the same problem. | Wrong trial balance for any past date. |
| 9 | Balance Sheet export | Used all-time balances and left out retained earnings. | The exported balance sheet didn't balance and didn't match the screen. |
| 10 | General Ledger report | The running balance started at zero every period. | Every balance-sheet account showed the wrong balance after the first year. It now shows an opening balance line. |
| 11 | AR / AP aging | Added foreign-currency amounts at face value under the base currency symbol, and ignored returns. | Aging totals didn't match the ledger. |
| 12 | **Security**: AI API key | The Anthropic API key was saved in the settings, so it ended up in **every backup file, every local snapshot and the cloud sync upload**. | Anyone you sent a backup to, and every member of a shared cloud company, got your API key. Backups and sync no longer carry it, and restoring a backup keeps the key already on the device. |
| 13 | Restoring old backups | Restoring a backup made by an older version skipped all the upgrade steps. | Missing accounts and settings (for example deferred tax) that newer screens expect. Old backups now go through the same upgrade as stored data. |
| 14 | Landed cost with FIFO | Freight and duty were added to the item's cost but not to its FIFO layers. | Under FIFO, landed cost disappeared from cost of sales while it stayed in the inventory account. |
| 15 | Credit/debit note pages | VAT wasn't rounded to the cent. Errors (like a locked period) failed silently. Returns made from an invoice showed "—" as the linked invoice. | Small ledger rounding noise, and a button that looked broken. |

## Improvements added

- **Code health:** `store.js` split into 11 slices under `src/store/` (same store, same actions — checked key by key). ESLint in CI. Playwright end-to-end tests in CI. A guard test that every relative import resolves.
- **Speed:** the Arabic dictionary loads only when Arabic is used — the main bundle went from 646 KB to 490 KB. The AI SDK loads only when the assistant is opened.
- **Security:** the AI assistant can run through a Supabase Edge Function (`supabase/functions/ai-chat`) that holds the API key server-side, checks company membership, allowlists models and caps tokens.
- **Month-End Close** page: depreciation, recurring schedules, bank reconciliation, FX revaluation, approvals, integrity check, then lock — each checked from the books.
- **UI:** in-app dialogs replace every browser alert, confirm and reason prompt (styled, translated, right-to-left, the action's verb on the button); one colour system instead of two; text and buttons raised to 4.5:1 contrast in both themes; translated report headers; a shared `Money` component; compact rows; keyboard shortcuts with a `?` help sheet.

## Third round: the leftovers (done)

- **Receipt scanning through the server.** The `ai-chat` function has a narrow `receipt` task (one image, one short instruction, JSON back). Expense Claims uses it when the cloud assistant is on, so no browser key is needed. CI now type-checks the function with Deno.
- **One status colour map.** `statusColor()` covers every status in the app by meaning (grey not started or finished, blue under way, amber needs someone, green good outcome, red a problem). Twelve screens had their own maps and disagreed; a test now fails if one comes back.
- **Sentence-case titles.** 70 page titles plus the sidebar and search-palette labels, with acronyms kept (CRM, FX, VAT, POS) and every Arabic translation carried over.

## Fourth round: new features

- **Bank statement import.** Reconciliation reads OFX/QFX, CAMT.053 (XML) and MT940 files as well as CSV (`src/utils/bankStatement.js`). The statement's closing balance fills itself in. Matching prefers the entry whose reference appears in the bank narrative, then the closest date. A line that isn't in the books yet, but pays an open invoice or bill (its number or the customer's name is in the narrative, or it is the only open document for that amount), is offered as **Record payment**, which posts the receipt and clears it in one step.
- **Roles and permissions.** New roles: sales clerk, purchasing clerk and HR officer, alongside owner, admin, accountant and viewer. Every store action that changes data is checked against the signed-in user's role (`src/store/guard.js`), so hiding a button is not the only protection. Internal postings made on the user's behalf (the journal entry behind a receipt) are allowed, and the app's own schedules and sync run as the system. Menus, search and pages leave out what a role can't open, and delete/void buttons are hidden. Owners and admins can adjust each role on the Team page; owner and admin themselves can't be narrowed. A test fails if a new store action is added without a permission.
- **Notifications bell.** Overdue invoices (net of returns), supplier bills overdue or due this week, low stock, approvals waiting for you, cheques due, contracts ending, accounts over budget, and last month not yet closed. Filtered by role. Dismissed items come back when something new joins them. Optional desktop notifications.
- **Offline.** The service worker now saves every file of the app on first visit (the list is filled in at build time), so pages never opened before work offline. An offline notice, and an "update ready" prompt instead of swapping files under a running page.
- **Email.** Invoices, statements and payment reminders have an **Email** button. Cloud companies send from the app through the `send-email` function (Resend; the key stays on the server; the email is built on the server from plain text, so it can't be used to send arbitrary HTML; daily limit; every send logged). Local companies get the same message in their own email app.
- **Customer portal.** A secret link per customer (`portal_links` table, `portal` function) shows that customer their invoices, payments, returns and balance, and lets them print an invoice. Only fields a printed invoice shows leave the server. Links can be cancelled.
- **Sentence-case buttons.** About 165 button labels and pop-up titles, with every Arabic translation carried over.
- **Bug fixed on the way:** payment reminders chased customers for amounts already returned (credit notes were ignored), and included drafts.

Setup for email and the portal: `docs/EMAIL-AND-PORTAL.md`.
